# Cloudflare Tunnel — Setup and VM Deployment

## Overview

The Cloudflare Tunnel exposes the teoria-engine stack (nginx → gateway → vLLM) to the internet via `llm.jambu.ai` without opening ports or exposing the host. Traffic flows:

```
Internet → Cloudflare edge → cloudflared (tunnel) → nginx:80 → gateway → vLLM
```

## Prerequisites

- Domain `jambu.ai` (or your hostname) in Cloudflare
- Nameservers pointing to Cloudflare
- `cloudflared` CLI installed for one-time provisioning

## 1. One-Time Provisioning (Local / Dev Machine)

Run locally on a machine with browser access (for Cloudflare login):

```bash
# Install cloudflared (if needed)
# Ubuntu/Debian: sudo apt-get install cloudflared
# macOS: brew install cloudflared

bin/setup-tunnel
```

This will:

1. **Install** `cloudflared/config.yml` from `config/engine.yml` (tunnel section) — versioned with the project
2. Open browser for Cloudflare login
3. Create tunnel (name/hostname from engine.yml)
4. Route DNS
5. Copy credentials to `cloudflared/tunnel.json`

To regenerate the config only (e.g. after changing `config/engine.yml`):

```bash
bin/load-config install-cloudflared-config
```

**Alternative (existing credentials):**

```bash
bin/setup-tunnel --credentials ~/.cloudflared/<tunnel-id>.json
```

## 2. Local Test (Optional)

With the stack running locally (or via SSH tunnel to VM):

```bash
# Start stack with tunnel
make up

# Verify tunnel container
docker compose --profile tunnel ps

# Test public URL (after DNS propagates, ~1–2 min)
curl -s https://llm.jambu.ai/health
curl -s -X POST https://llm.jambu.ai/api/v1/chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -d '{"input":"Hi","stream":false}'
```

## 3. Deploy to VM (Vast.ai / Remote GPU)

1. **Copy credentials to VM** (secure transfer):

```bash
scp -P 35543 -i ~/.ssh/id_rsa \
  cloudflared/tunnel.json \
  root@85.218.235.6:/opt/teoria-engine/cloudflared/
```

2. **Ensure cloudflared config exists on VM:**

```bash
# config.yml should already be in the repo
ls /opt/teoria-engine/cloudflared/
# config.yml  tunnel.json
```

3. **Start stack with tunnel:**

```bash
ssh -p 35543 root@85.218.235.6 -i ~/.ssh/id_rsa \
  'export PATH="$HOME/.local/bin:$PATH" && cd /opt/teoria-engine && make up'
```

The `teoria-engine` script detects `cloudflared/tunnel.json` and adds the `--profile tunnel` flag, so the cloudflared container starts automatically.

4. **Verify:**

```bash
curl -s https://llm.jambu.ai/health
```

## 4. Connectivity

- **Port 7844**: cloudflared must reach Cloudflare (outbound). No inbound ports needed.
- **Firewall**: No port forwarding required on the VM or router.

## 5. Security

- `tunnel.json` is equivalent to an API key for the tunnel. Never commit it.
- On the VM, use `chmod 644 cloudflared/tunnel.json` — the cloudflared container runs as non-root and needs read access. (Do **not** use 600 with root-owned files; the container UID won't be able to read it.)
- Use a secrets manager (Vault, SSM) for production deployments.

## 5.1 Key Lessons from Setup

- **Use tunnel UUID, not name**: `config.yml` must reference the tunnel UUID (e.g. `tunnel: a550eb52-...`), not the name (`llm-server`). Using a name requires `cert.pem` at runtime, which is only generated by `cloudflared tunnel login` and should not be deployed to production. The UUID + `tunnel.json` is sufficient.
- **Config is generated**: `cloudflared/config.yml` is generated from `config/engine.yml` via `bin/load-config install-cloudflared-config`. The tunnel UUID is stored in `config/engine.yml` under `tunnel.id`.

## 6. Troubleshooting

| Issue | Check |
|-------|-------|
| Tunnel not starting | `cloudflared/tunnel.json` exists? `docker compose --profile tunnel ps` |
| 502 Bad Gateway | nginx/gateway/vLLM healthy? `make health` |
| DNS not resolving | `cloudflared tunnel route dns` ran? Wait 1–2 min for propagation |
| Connection refused | cloudflared can reach Cloudflare on 7844? |

Logs:

```bash
docker compose --profile tunnel logs cloudflared
```
